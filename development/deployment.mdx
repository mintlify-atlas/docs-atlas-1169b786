The production deployment separates the JavaScript bundle from the data it reads. The compiled, obfuscated bundle is a small set of hash-named static files that can be served from any static host. The prop libraries, maps, and registry files (roughly 220 MB total) live in a Cloudflare R2 bucket and are fetched at runtime via the `/assets/` path prefix. Because the R2 tree is shared between the editor and the game, uploading it once serves both.

## Production architecture

```
Browser
  │
  ├─► Static host (Cloudflare Pages, Nginx, etc.)
  │     dist/assets/<hash>.js     ← compiled + obfuscated bundle
  │     dist/index.html
  │
  └─► Cloudflare R2 bucket  (mounted at /assets/)
        props/<library>/library.xml
        props/<library>/<prop>.3ds
        props/<library>/<texture>.jpg
        maps/summer/<map_id>.xml
        editor-maps.json
        editor-props.json
        embedded/ui/life_*.png
```

The bundle is built with `VITE_ASSET_BASE=/assets/` so every `assetUrl()` call in the source resolves paths against the R2 origin rather than the bundle's own origin.

## Full deploy workflow

<Steps>

### Set the required environment variables

`scripts/upload-assets.mjs` authenticates against Cloudflare's S3-compatible R2 API. Export these three variables in your shell (or CI environment) before running the upload:

```bash
export R2_ACCOUNT_ID="your-cloudflare-account-id"
export R2_ACCESS_KEY_ID="your-r2-access-key-id"
export R2_SECRET_ACCESS_KEY="your-r2-secret-access-key"
```

Optionally override the bucket name (defaults to `skilltanki-assets`):

```bash
export R2_BUCKET="your-bucket-name"
```

### Upload prop and map assets to R2

Run the uploader from the editor package. It walks `public/` and uploads every file into the R2 bucket at the matching key, setting the correct `Content-Type` for each extension:

```bash
node scripts/upload-assets.mjs
```

The upload is **idempotent**. Before sending any file the script lists the entire bucket and compares each candidate's byte size and MD5 hash against the existing object. Files that already match are silently skipped, so a re-run after a partial failure or a deploy of a new editor version that shares most of its assets costs almost nothing.

<Note>
  `scripts/upload-assets.mjs` reads from `public/`, which in the monorepo is generated by `scripts/sync-assets.mjs` from the canonical `../../assets` source tree. In a standalone checkout, `public/` already holds the committed data, so you can run the uploader directly without a sync step — as long as the committed data is what you intend to publish.
</Note>

### Build the production bundle

Type-check the source and compile the bundle with the R2 asset base set:

```bash
npx tsc --noEmit && VITE_ASSET_BASE=/assets/ npx vite build
```

Vite writes the output to `dist/`. The bundle is minified with terser, then obfuscated with javascript-obfuscator. All chunk and entry files receive hash-only names (`assets/<hash>.js`) so the module map does not leak through URL paths. `public/` is **not** copied into `dist/` — assets are served from R2, not bundled alongside the JavaScript.

### Deploy dist/ to your static host

Copy the contents of `dist/` to any static host. Cloudflare Pages, Nginx, and any CDN that can serve static files will work. No server-side logic is required — the editor is a fully client-side application.

```bash
# Example: deploy with Wrangler to Cloudflare Pages
npx wrangler pages deploy dist/
```

The `index.html` and the `assets/<hash>.js` chunks are the only files that need to be served from this host.

</Steps>

## Local R2 testing with workerd

Pass the `--local` flag to target a local workerd instance (via Wrangler) instead of the real R2 bucket. No credentials are needed:

```bash
node scripts/upload-assets.mjs --local
```

In local mode the script shells out to `npx wrangler r2 object put --local` for each file. The local R2 state is managed by the **server** package's Wrangler configuration; `--local` uploads are sent to `packages/server/.wrangler/` so the correct binding is in scope.

You can also limit the upload to the first N files for quick smoke tests:

```bash
node scripts/upload-assets.mjs --local --limit=20
```

## Content-Type mapping

The uploader sets `Content-Type` at upload time. Cloudflare's edge uses this header to decide which responses to compress — compressible types (JSON, XML, JavaScript) are gzip-compressed at the edge; binary types (`.3ds`, images) are not. The map covers all file types in the asset tree:

| Extension | Content-Type |
|---|---|
| `.json` | `application/json` |
| `.xml` | `application/xml` |
| `.js` | `text/javascript` |
| `.png` | `image/png` |
| `.jpg` / `.jpeg` | `image/jpeg` |
| `.webp` | `image/webp` |
| `.3ds` | `application/octet-stream` |
| `.mp3` | `audio/mpeg` |
| `.wav` | `audio/wav` |
